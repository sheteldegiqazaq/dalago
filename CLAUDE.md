# DalaGo

Цифровой B2B-маркетплейс, который объединяет фермеров, местных производителей и
малый бизнес Казахстана. Производители находят покупателей, а магазины, кафе и
рестораны ищут поставщиков, сравнивают цены, размещают оптовые заявки и получают
предложения. ИИ помогает создавать объявления и искать товары обычным языком.

Старт: Семей и область Абай. Дальше планируется масштабирование на весь Казахстан.

**Контекст: проект делается на хакатоне.** Приоритет у работающего демо-сценария
от начала до конца, а не у полноты. Делай простое и рабочее, не строй
инфраструктуру «на вырост».

## Структура репозитория

```txt
backend/    NestJS 11 + Prisma 7 + PostgreSQL. Правила: backend/AGENTS.md
frontend/   Next.js 15 App Router + shadcn/ui + TanStack Query + Orval. Правила: frontend/AGENTS.md
.claude/skills/documentation/   скилл для PRD, требований и плана реализации
docs/       продуктовая документация (PRD), создаётся скиллом documentation
```

Перед изменениями в `backend/` или `frontend/` следуй их `AGENTS.md` и `docs/`.

## Роли пользователей

- **Поставщик (SUPPLIER)**: фермер или производитель. Размещает товары
  (объявления), отвечает на оптовые заявки предложениями.
- **Покупатель (BUYER)**: магазин, кафе или ресторан. Ищет товары, сравнивает
  цены, создаёт оптовые заявки и принимает предложения.
- **Админ (ADMIN)**: модерация.

## MVP для демо

1. Регистрация и вход (email + пароль, JWT), выбор роли и профиль компании
   (название, город или район области Абай, телефон).
2. Каталог товаров: категории (овощи, фрукты, мясо, молочка, зерно, мёд и т.д.),
   цена за единицу (кг, л, шт, т), минимальный оптовый объём, регион, фото по URL.
3. Поиск и фильтры: категория, регион, цена; сортировка по цене для сравнения.
4. Оптовые заявки (RFQ): покупатель пишет, что ему нужно (товар, объём, срок,
   место доставки). Поставщики присылают предложения (цена, срок), покупатель
   принимает одно из них.
5. **ИИ-функции** (главная фишка, на демо показывать первыми):
   - **ИИ-объявление**: поставщик пишет свободным текстом («продаю 2 тонны
     картошки, 150 тг за кило, Семей, доставка своя»), ИИ возвращает
     заполненную форму объявления (название, категория, цена, единица, объём,
     регион, описание). Пользователь проверяет и публикует.
   - **ИИ-поиск**: покупатель пишет «нужно 50 кг свежей говядины для кафе в
     Семее до пятницы», ИИ превращает запрос в структурированные фильтры и
     находит подходящие товары. Если товаров нет, предлагает создать заявку.

Вне MVP (не делать без явной просьбы): онлайн-оплата, логистика и трекинг,
чат в реальном времени, мобильное приложение, рейтинги и отзывы.

## Модель данных (черновик, уточнять по ходу)

- `User`: email, passwordHash, role (BUYER | SUPPLIER | ADMIN)
- `Company`: userId, name, type (FARM | PRODUCER | SHOP | CAFE | RESTAURANT), region, city, phone
- `Category`: name, slug
- `Product` (объявление): supplierCompanyId, categoryId, title, description,
  price, unit, minOrderQty, availableQty, region, imageUrl, status
- `PurchaseRequest` (оптовая заявка): buyerCompanyId, categoryId, title,
  description, quantity, unit, deadline, deliveryCity, status (OPEN | CLOSED)
- `Offer` (предложение): requestId, supplierCompanyId, pricePerUnit, quantity,
  deliveryDate, comment, status (PENDING | ACCEPTED | REJECTED)

Деньги хранить в тенге как `Decimal`. Регионы и города вынести в enum или
справочник: на старте это область Абай (Семей, Аягоз, Курчатов, Абай и т.д.).

## ИИ (Claude API)

- Вызовы Claude делаются **только с бэкенда**, ключ лежит в `backend/.env`
  (`ANTHROPIC_API_KEY`, модель в `ANTHROPIC_MODEL`). На фронт ключ не попадает.
- SDK: `@anthropic-ai/sdk` (уже установлен). Перед написанием кода с Claude API
  загрузи скилл `claude-api`: там актуальные модели и параметры.
- Структурированный ответ (поля объявления, фильтры поиска) получай через
  tool use или structured outputs, а результат валидируй через class-validator.
- По правилам backend/AGENTS.md: модуль `ai`, порт (интерфейс) в use case,
  адаптер на Anthropic SDK в `gateways/`. В unit-тестах подменяй порт фейком.
- Если ключа нет, бэкенд не должен падать: возвращай понятную ошибку.
- Тексты для пользователя на русском (позже добавить казахский).

## Как связаны фронт и бэк

1. Бэкенд при старте пишет OpenAPI в `backend/uploads/openapi/openapi-spec.json`.
2. `cd frontend && pnpm orval` генерирует типизированный клиент в
   `src/shared/api/generated.ts` (руками не редактировать).
3. После любого изменения API: перезапусти бэкенд, затем `pnpm orval`.

## Локальный запуск

```bash
# backend (порт 4000). База: docker compose up -d ИЛИ pnpm db:local (PostgreSQL без Docker)
cd backend && docker compose up -d && pnpm install && pnpm prisma:migrate && pnpm db:seed && pnpm start:dev
# frontend (порт 3000)
cd frontend && pnpm install && pnpm orval && pnpm dev
```

## Проверки перед тем, как сказать «готово»

```bash
cd backend  && pnpm lint && pnpm test && pnpm build
cd frontend && pnpm lint && pnpm test:run && pnpm build
# сквозные: backend pnpm test:e2e (API), frontend pnpm test:e2e (Playwright)
```

Продукт называется **DalaGo** везде: в интерфейсе, документах и коде. Демо-аккаунты создаёт `pnpm db:seed`
(пароль `demo12345`), документы для защиты лежат в `docs/`.

## Язык и стиль

- Интерфейс по умолчанию на русском, i18n через next-intl (`ru`, `kk`).
- Код, имена и коммиты на английском, комментарии и доки можно на русском.
- Не добавляй Redis, очереди, S3 или микросервисы: для хакатона это лишнее.
