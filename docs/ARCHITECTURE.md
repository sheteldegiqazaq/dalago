# Архитектура DalaGo

## Общая схема

```text
Браузер (Next.js 15, App Router, kk/ru)
   │  HTTPS, JSON, Authorization: Bearer <JWT>
   ▼
NestJS 11 API (/api, OpenAPI → /api/docs)
   ├─ accounts       регистрация, вход, профиль пользователя
   ├─ reference      регионы, города, категории
   ├─ companies      каталог поставщиков, статистика по городам, профиль компании
   ├─ products       каталог, поиск, CRUD объявлений
   ├─ procurement    оптовые заявки и предложения (жизненный цикл)
   ├─ inquiries      переписка компаний
   ├─ dashboard      сводки кабинетов, показатели площадки
   └─ ai             ИИ-объявление и ИИ-поиск (Claude или правила)
   ▼
PostgreSQL (Prisma 7, миграции)          Claude API (только с сервера)
```

## Фронтенд

- Next.js 15 + TypeScript strict + Tailwind 4 + shadcn/ui, иконки Lucide.
- Архитектура `app → modules → entities → shared`, правила проверяет `dependency-cruiser` (`pnpm lint:deps`):
  UI не импортирует сгенерированный клиент напрямую, модули общаются только через `index.ts`.
- Типизированный клиент генерирует Orval из OpenAPI бэкенда (`pnpm orval`).
- Серверное состояние — TanStack Query; фильтры каталога, поставщиков, заявок и вкладки кабинета — в URL (nuqs).
- Формы — react-hook-form + zod, тексты ошибок переведены.
- i18n — next-intl, словари `frontend/messages/kk.json` и `ru.json`, язык по умолчанию — казахский.
  Ошибки API приходят со стабильным `code` и переводятся на клиенте.
- Шрифты Inter и Lora с подмножеством `cyrillic-ext` (казахские буквы).

## Бэкенд

- NestJS: модульный монолит, вертикальные срезы (controller → use case → repository interface → Prisma),
  внешние зависимости через порты (хеширование паролей, выпуск JWT, Claude). Правила — `backend/docs`.
- Валидация входа — class-validator (whitelist, запрет лишних полей). Ответ ИИ валидируется так же.
- Ошибки: `DomainException` (400), `Forbidden…` (403), `NotFound…` (404), `Unauthorized…` (401), все с `code`.
  В лог пишутся имя и сообщение ошибки, без тел запросов и персональных данных.

## База данных

| Таблица | Назначение |
| --- | --- |
| `users` | email, хеш пароля, роль (`BUYER`, `SUPPLIER`, `ADMIN`), язык интерфейса |
| `companies` | компания пользователя: название, тип, город, телефон, описание, `isDemo` |
| `regions`, `cities` | справочник; область Абай активна, остальные регионы — следующий этап; приблизительные координаты центров населённых пунктов |
| `categories` | категории с названиями на ru/kk |
| `products` | объявление: названия и описания ru/kk, цена (`Decimal`, тенге), единица, остаток, минимальный заказ, доставка/самовывоз, теги, `searchText`, статус, `isDemo` |
| `purchase_requests` | оптовая заявка: объём, единица, желаемая цена, город и дата доставки, статус |
| `offers` | предложение поставщика: объём, цена, доставка, срок, условия, статус; одно на поставщика в заявке |
| `inquiries`, `inquiry_messages` | переписка между двумя компаниями, опционально по товару или заявке |

Ограничения в базе: внешние ключи, уникальность `(requestId, supplierCompanyId)`, CHECK на положительные
цены и количества, запрет переписки компании с самой собой, индексы по статусу, категории, городу и цене.

Упрощение MVP: у пользователя ровно одна компания (`companies.ownerUserId` уникален). Таблица
участников компании (`business_members`) — следующий шаг.

### Жизненный цикл заявки

```text
OPEN ──(первое предложение)──▶ OFFERS_RECEIVED ──(покупатель принял)──▶ ACCEPTED
  └──────────────(покупатель закрыл)──────┴────────────────────────────▶ CLOSED
```

- Правила — чистые функции в `backend/src/modules/procurement/services/request-lifecycle.ts` с тестами.
- Принятие предложения — одна транзакция: условные `updateMany` защищают от двойного принятия,
  остальные ожидающие предложения отклоняются. Закрытие заявки отклоняет все ожидающие.

## Аутентификация и права доступа

- Email + пароль, хеш scrypt (стандартная библиотека Node). JWT на 7 дней (`JWT_EXPIRES_IN_SECONDS`),
  в токене `sub`, `role`, `companyId`. Refresh-токенов в MVP нет; токен хранится в localStorage браузера.
- Все проверки — на сервере (фронтенд-гарды только для удобства):

| Правило | Где проверяется |
| --- | --- |
| Объявления создаёт только `SUPPLIER`, изменяет и удаляет только владелец | `products`: `@Authorization('SUPPLIER')` + `ProductOwnership` |
| Снятое с публикации объявление видит только владелец | `GetProductUseCase` |
| Заявки создаёт, меняет и закрывает только автор-покупатель | `procurement`: `assertRequestOwner`, `assertRequestModifiable` |
| Все предложения видит только автор заявки; поставщик — только своё | `request-visibility.ts` |
| Телефон покупателя видят только участники заявки | `request-visibility.ts` |
| Завершённые заявки скрыты от посторонних (404) | `request-visibility.ts` |
| Переписку читают и пишут только две компании-участницы (иначе 404) | `inquiry-access.ts` |
| Служебный API пользователей — только `ADMIN` | `users.controller.ts` |

Проверено e2e-тестами `backend/test/marketplace.e2e-spec.ts` (401/403/404 для чужих данных).

## ИИ

| Функция | Эндпоинт | Что делает |
| --- | --- | --- |
| ИИ-объявление | `POST /api/ai/listing-draft` (поставщик) | Свободный текст → черновик формы. Ничего не публикует |
| ИИ-поиск | `POST /api/ai/search` | Запрос → фильтры → поиск по реальной базе через `ProductsFacade` |
| Статус | `GET /api/ai/status` | Какой режим активен: `claude` или `rules` |

- Порт `AiAssistant` и два адаптера: `AnthropicAiAssistant` (SDK `@anthropic-ai/sdk`, structured outputs
  через `output_config.format` с JSON-схемой, `effort: low`, таймаут 20 с) и `RuleBasedAiAssistant`
  (словари ru/kk/en, казахские падежные формы, единицы, цены, сроки «до пятницы / жұмаға дейін»).
- `AiRunner`: нет ключа → правила (`notice: AI_NOT_CONFIGURED`); ошибка или отказ Claude → правила
  (`notice: AI_UNAVAILABLE_FALLBACK`). Ответ всегда сообщает фактический режим; интерфейс его подписывает.
- Защита от выдумок: ответ модели валидируется class-validator; категории и города вне справочника обнуляются;
  если в исходном тексте нет цифр, цена и объём обнуляются; ИИ-поиск без распознанного товара не показывает каталог.
- Если строгий поиск пуст, условия ослабляются (цена, объём, город), и это показано пользователю.
  Если пусто и так — предлагаем создать заявку с подставленными полями.
- Ограничение частоты: 15 запросов в минуту на пользователя или IP (в памяти процесса).
- Приватность: в Claude уходят только текст запроса или объявления и справочники категорий и городов.
- Модель задаётся `ANTHROPIC_MODEL` (по умолчанию `claude-sonnet-5-5`). Режим Claude не проверялся
  в этой сборке из-за отсутствия ключа: протестированы резервный режим и переключение на него при ошибке.

## Демо-режим

- Сид `backend/src/app/database/seeding/seed-database.ts`: справочники + 10 вымышленных компаний
  (`@demo.dalago.kz`, телефоны `+7 000 …`), 21 товар, заявки во всех статусах, предложения, две переписки.
  Все записи `isDemo = true` и подписаны в интерфейсе. Повторный запуск пересоздаёт демо-данные.
- Демо-вход — обычный вход по опубликованному паролю, обхода аутентификации нет.
  Кнопки демо скрываются `NEXT_PUBLIC_DEMO_MODE=false`; сид в продакшене блокирован (`SEED_ALLOW_PRODUCTION`).

## Открытые данные

- Показатели внесены вручную из публикаций stat.gov.kz (страница региона, мониторинг МСП, ВРП)
  с периодом, датой публикации и датой обращения (20.10.2026): `frontend/src/modules/open-data/model/constants/region-facts.ts`.
- API stat.gov.kz и data.egov.kz не подключены; это указано на странице и в каталоге источников.
- Показатели площадки считаются из базы (`GET /api/dashboard/marketplace-stats`) и подписаны как демо-данные.

## Развёртывание

- Бэкенд и фронтенд имеют Dockerfile (`output: standalone` у Next.js); PostgreSQL — `backend/docker-compose.yml`.
- Без Docker: `pnpm db:local` запускает PostgreSQL 18 из пакета `embedded-postgres` (данные сохраняются).
- Переменные: `backend/.env.example`, `frontend/.env.example`. Секреты в репозиторий не попадают (`.env` в `.gitignore`).
- Порядок: миграции `pnpm prisma:deploy` → `pnpm db:seed` (только для демо) → `pnpm start:prod`.

## Ограничения безопасности MVP

- JWT в localStorage уязвим при XSS; для продакшена — httpOnly-cookie и refresh-токены.
- Ограничение частоты ИИ хранится в памяти одного процесса.
- Нет подтверждения email, сброса пароля и верификации компаний.
- Нет уведомлений: о новом предложении или сообщении пользователь узнаёт, открыв кабинет.
- Нет аудита действий администратора и модерации.
