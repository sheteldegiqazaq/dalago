# Сценарий живого демо (3 минуты)

Сценарий повторяет то, что проверяет браузерный тест `frontend/tests/e2e/demo-flow.spec.ts`.
Все названия кнопок даны так, как они выглядят в интерфейсе (RU / KK).

## Подготовка (за 10 минут до выступления)

1. Запустить базу, бэкенд и фронтенд (см. корневой README).
2. Сбросить демо-данные: `cd backend && pnpm db:seed` — все прошлые тестовые заявки удалятся.
3. Открыть две вкладки браузера:
   - вкладка А: `http://localhost:3000/kk` (покупатель);
   - вкладка Б: `http://localhost:3000/ru/demo` в режиме инкогнито (поставщик).
     Токен хранится в localStorage, поэтому разные окна = разные аккаунты.
4. Проверить на `/ru/catalog`, какой режим ИИ показан: «Работает модель Claude» или
   «Резервный режим». Говорить жюри то, что видно на экране.
5. Шрифт браузера 110–125%, чтобы было видно с дальних рядов.

## Запасной план

| Проблема | Что делать |
| --- | --- |
| Нет интернета / ключа Claude | Всё работает в резервном режиме на правилах. Сказать: «Сейчас работает резервный режим — он честно подписан на экране». |
| Бэкенд упал | `cd backend && pnpm start:dev`; база поднимается `pnpm db:local` (или Docker). |
| Демо-данные «испорчены» прошлым прогоном | `pnpm db:seed` пересоздаёт демо-компании и сделки (~5 секунд). |
| Нужно показать без двух вкладок | После шага поставщика нажать **Выйти** и снова **Войти как покупатель** на `/ru/demo`. |
