# DalaGo

B2B-площадка оптовых закупок у местных производителей Семея и области Абай.
Фермеры и производители публикуют товары и отвечают на заявки; магазины, кафе и столовые
ищут поставщиков, размещают оптовые заявки, сравнивают предложения и выбирают лучшее.
ИИ-помощник на казахском и русском заполняет объявления и понимает поисковые запросы обычным языком.

**Сейчас на площадке только примеры данных: все компании, товары и сделки вымышленные.**

**Сайт: https://dalago.vercel.app** (попробовать без регистрации — кнопка «Попробовать» в шапке сайта).
API: https://dalago-api.vercel.app/api/health, Swagger: https://dalago-api.vercel.app/api/docs.

- Документация: [docs/](docs/README.md) — архитектура, план пилота, сценарий показа и презентация.
- Правила для Claude Code и разработчиков: [CLAUDE.md](CLAUDE.md), `backend/docs`, `frontend/AGENTS.md`.

## Что реализовано

| Раздел | Адрес | Статус |
| --- | --- | --- |
| Главная, переключатель ҚАЗ/РУС | `/kk`, `/ru` | Работает |
| Каталог: поиск, категория, город, цена, нужный объём, доставка, сортировка, страницы | `/catalog` | Работает на данных базы |
| ИИ-поиск обычным языком | `/catalog` | Claude при наличии ключа, иначе подписанный резервный режим |
| Карточка товара, написать поставщику, заявка на товар | `/products/:id` | Работает |
| Каталог и профили поставщиков | `/suppliers` | Работает |
| Доска оптовых заявок, создание и изменение заявки | `/requests`, `/requests/new` | Работает |
| Предложения поставщиков, сравнение, принятие и отклонение, закрытие заявки | `/requests/:id` | Работает, проверки на сервере |
| Кабинеты покупателя и поставщика: сводка, события, мои заявки, товары, предложения, профиль | `/dashboard` | Работает |
| Объявление с ИИ-помощником и предпросмотром | `/dashboard/products/new` | Работает |
| Переписка компаний | `/inquiries` | Сохраняется в базе, без real-time |
| Карта-схема поставщиков | `/map` | Схема, не картографическая подложка |
| Открытые данные с источниками | `/open-data` | Официальные цифры внесены вручную со ссылками; API не подключён |
| О проекте: бизнес-модель, пилот, ограничения | `/about` | Работает |
| Попробовать без регистрации: вход в аккаунт-пример одним нажатием | `/try` | Аккаунты-примеры из сида |

Вне MVP: онлайн-оплата, логистика, уведомления в реальном времени, рейтинги, верификация компаний, мобильное приложение.

## Запуск с примерами данных

Около 5 минут. Нужны **Node.js 22+** и **pnpm** (`npm i -g pnpm` или `corepack enable`).
Docker не обязателен. Команды одинаково работают в bash, macOS Terminal и Windows PowerShell.
Понадобятся три терминала: база, бэкенд, фронтенд.

```bash
git clone https://github.com/sheteldegiqazaq/dalago.git
cd dalago
```

### Терминал 1 — база данных PostgreSQL

Без Docker: встроенный PostgreSQL 18, ставится вместе с зависимостями. Окно не закрывайте.

```bash
cd backend
cp .env.example .env          # для локальной проверки менять ничего не нужно
pnpm install
pnpm db:local                 # ждите строку «PostgreSQL is running»
```

Вместо этого можно через Docker: `cd backend && cp .env.example .env && pnpm install && docker compose up -d`.

> Если порт 5432 уже занят другим PostgreSQL, перед запуском замените в `backend/.env` порт
> `5432` на `5434` в двух строках: `POSTGRES_PORT` и `DATABASE_URL`.

### Терминал 2 — бэкенд API (http://localhost:4000/api, Swagger: http://localhost:4000/api/docs)

```bash
cd backend
pnpm prisma:deploy            # создать таблицы
pnpm db:seed                  # справочники и примеры данных: 10 вымышленных компаний, 21 товар, заявки, предложения
pnpm start:dev                # ждите строку «Nest application successfully started»
```

### Терминал 3 — фронтенд (http://localhost:3000)

```bash
cd frontend
cp .env.example .env
pnpm install
pnpm dev
```

Откройте http://localhost:3000. Клиент API (`src/shared/api/generated.ts`) уже в репозитории, `pnpm orval`
нужен только после изменения API.

### Путь пользователя для проверки

На странице http://localhost:3000/ru/try вход в аккаунт-пример одной кнопкой, без пароля.
Для входа по email пароль аккаунтов-примеров `dalago12345`:

| Роль | Email |
| --- | --- |
| Покупатель (кафе) | `buyer@dalago.example` |
| Поставщик (овощи) | `supplier@dalago.example` |

1. **Каталог.** Откройте «Каталог», отфильтруйте по категории и городу, отсортируйте по цене.
   В ИИ-поиск введите «нужно 50 кг говядины для кафе в Семее до пятницы».
2. **Заявка покупателя.** Войдите как покупатель → «Заявки» → «Создать заявку» → заполните и опубликуйте.
3. **Предложение поставщика.** Выйдите, войдите как поставщик → откройте эту заявку → отправьте предложение.
4. **Выбор предложения.** Снова войдите как покупатель → в заявке примите предложение. Статус заявки станет «Поставщик выбран».
5. **Объявление с ИИ.** Как поставщик: «Кабинет» → «Новое объявление» → напишите «продаю 2 тонны картошки,
   150 тг за кило, Семей, доставка своя» → проверьте заполненную форму → опубликуйте. Товар появится в каталоге.
6. **Переписка.** На карточке товара нажмите «Написать поставщику». Сообщение появится в разделе «Сообщения».
7. Переключите язык ҚАЗ/РУС в шапке.

**Проверка сохранения данных.** Остановите бэкенд и базу (Ctrl+C в терминалах 1 и 2) и запустите снова
(`pnpm db:local`, затем `pnpm start:dev`, без `db:seed`). Созданные заявки, предложения, товары и сообщения
останутся на месте: всё хранится в PostgreSQL. Файлы встроенной базы лежат в `backend/.local-db`.
Если путь к проекту содержит не-ASCII символы, например `C:\Users\админ`, они лежат в `C:\ProgramData\dalago-db`.
В Docker данные лежат в томе `postgres_data`.

**Сброс к исходным примерам данных:** `cd backend && pnpm db:seed`. Сид удаляет аккаунты компаний-примеров со всем,
что они создали, и создаёт их заново. Аккаунты, которые вы зарегистрировали сами, остаются.

Без ключа `ANTHROPIC_API_KEY` ИИ-функции работают в резервном режиме на правилах, и интерфейс это подписывает.
Чтобы включить Claude, впишите ключ в `backend/.env` и перезапустите бэкенд.

**Автоматическая проверка пути пользователя** (бэкенд и фронтенд запущены, примеры данных загружены):

```bash
cd frontend
pnpm exec playwright install chromium
pnpm test:e2e                 # 4 браузерных сценария, включая «заявка → предложение → принятие»
```

## Публикация в Vercel

Два проекта Vercel и база Neon (регион Франкфурт):

| Проект | Папка | Адрес |
| --- | --- | --- |
| `dalago` | `frontend/` | https://dalago.vercel.app |
| `dalago-api` | `backend/` | https://dalago-api.vercel.app |

- Бэкенд собирается `pnpm build`. Vercel запускает собранный `dist` через `backend/server.js`
  (настройки в `backend/vercel.json`).
- `DATABASE_URL` подставляет интеграция Neon. В Vercel заданы `JWT_SECRET`,
  `ALLOWED_ORIGIN=https://dalago.vercel.app` и `OPENAPI_OUTPUT_PATH=/tmp/openapi`.
- Во фронтенде задан `NEXT_PUBLIC_API_URL=https://dalago-api.vercel.app`; вход без регистрации включён по умолчанию.
- Публикация: `vercel deploy --prod` в папке `backend` или `frontend`.
- Миграции и сид для Neon запускаются локально, со строкой подключения `DATABASE_URL_UNPOOLED` из Vercel.

## Переменные окружения

| Файл | Переменная | Назначение |
| --- | --- | --- |
| `backend/.env` | `DATABASE_URL` | Строка подключения PostgreSQL |
| | `JWT_SECRET` | Секрет подписи токенов, длинная случайная строка |
| | `JWT_EXPIRES_IN_SECONDS` | Срок жизни токена, по умолчанию 7 дней |
| | `ANTHROPIC_API_KEY` | Ключ Claude API. Пусто — ИИ работает в резервном режиме на правилах |
| | `ANTHROPIC_MODEL` | Модель Claude, по умолчанию `claude-sonnet-5-5` |
| | `AI_RATE_LIMIT_PER_MINUTE` | Лимит ИИ-запросов на пользователя или IP |
| | `ALLOWED_ORIGIN` | Адрес фронтенда для CORS |
| `frontend/.env` | `NEXT_PUBLIC_API_URL` | Адрес бэкенда |
| | `NEXT_PUBLIC_SAMPLE_ACCESS` | `false` скрывает вход без регистрации в аккаунты-примеры |

Ключ Claude используется только на бэкенде и не попадает в браузер.

## Вход без регистрации

Откройте `/try` и нажмите «Войти как покупатель» или «Войти как поставщик».
Кнопки входят в общий аккаунт-пример (`POST /api/auth/sample-session`), список аккаунтов — в
[docs/WALKTHROUGH.md](docs/WALKTHROUGH.md). Прежний адрес страницы перенаправляется на `/try`.
Пересоздать примеры данных: `cd backend && pnpm db:seed`.

## Проверки

```bash
cd backend  && pnpm lint && pnpm test && pnpm build
cd backend  && pnpm test:e2e        # API-сценарий на реальной базе (нужен pnpm db:seed)
cd frontend && pnpm lint && pnpm test:run && pnpm build
cd frontend && pnpm test:e2e        # браузерный сценарий Playwright (нужны запущенные бэкенд и фронтенд)
```

Перед первым `pnpm test:e2e` во фронтенде: `pnpm exec playwright install chromium`.
